# Rutile 0.2 Implementation Plan

> Authority: `docs/superpowers/specs/2026-07-10-rutile-next-SPEC.md` (LD-1…LD-9) and
> `DESIGN-SYSTEM.md` + `design/tokens.css`. Base: main after the 0.1.1 release lands.
> Workers use `superpowers:executing-plans` per lane; every behavior change is
> red-green; reviewers are read-only; the orchestrator alone commits and merges.

**Goal:** 0.2 = the auto-formatting layer (SPEC §6), recipient-grade self-contained
HTML export (SPEC §7) themed by the committed design system, and the QoL set (SPEC §9)
— on both shells, without touching the frozen render/preview security seams.

**Non-goals (locked):** AI features (0.3), chance styling (0.3, C8), native chrome
redesign (separate discussion), multi-file/tabs, PDF export, sync. Typora-style
in-place rendering explicitly out (LD-3).

## Architecture stance

- §6 lives in `feathermark-core` as a pure, platform-neutral **FormatCommand engine**:
  `apply_format(document, selection, FormatCommand) -> EditPlan` (typed edits the
  existing `Document`/`EditorAdapter` contracts already know how to apply). Platform
  shells only bind keys/toolbar to commands and route through the existing reducer.
  No shell-local text mangling; one engine, two bindings.
- Smart paste = `html_to_markdown` converter in core (bounded input ≤ 2 MiB, typed
  errors, pure function — fuzzable from day one) + per-shell clipboard HTML readers.
- §7 export lives in core (`export::render_export_page`) reusing `render_markdown`'s
  pipeline with an **export template** that embeds `design/tokens.css`-derived styles
  inline; the app adds Save-as-HTML (native save panel) and Copy-as-HTML. Export page
  = zero JS, zero external requests, light+dark via `prefers-color-scheme`, print
  stylesheet (LD-4, DESIGN-SYSTEM refusals).
- §9 QoL: autosave/crash-recovery + session restore in `feathermark-app` (AppState/
  FileService own it; shells stay thin); find/replace as core text ops + shell UI;
  spellcheck = native platform facilities (NSTextView/GtkSourceView built-ins),
  config-only; counts computed in core, displayed in native status bars.

## Waves

### Wave 0 — Contracts (one writer, stop gate)
- Define `FormatCommand`, `EditPlan`, `ExportRequest/ExportError`, autosave/session
  state schema, find/replace op contracts in core (types only + contract tests).
- Architect review, then frozen for the release. **DONE** — frozen on branch
  `feat/0.2-wave0-contracts`; architect verdict APPROVE-WITH-NITS, pre-freeze fixes
  applied (ExportViolation non-exhaustive, session version envelope, session cap
  reconciliation).

#### Wave-0 architect findings deferred to Wave 1 (do not lose these)
- **1E export sanitizer must be an allowlist, not the Wave-0 denylist.** The frozen
  `ExportPage::from_html` inspector still misses inline event handlers (`onload=`,
  `onerror=`, `onclick=` on svg/body/img), relative and root-relative `src`
  (`src="x.png"`), and `data:text/html` in `href`. Wave 1 moves `src`/`url()` to an
  allowlist (only `data:` permitted) and adds `on*=` / `expression()` rejection, then
  Wave 4 security review confirms. Add the payload-carrying `ExportViolation` variants
  the non-exhaustive enum now allows.
- **1F/1Q replace-all + large-selection batching.** `EditPlan` caps at
  `MAX_PLAN_EDITS` (4096) and `MAX_PLAN_TOTAL_BYTES` (256 KiB). Replace-all of a common
  substring, or list/renumber over >4096 lines, will hit `TooManyEdits`/`PlanTooLarge`.
  Wave 1 must chunk replace-all across multiple plans and surface a specific typed error;
  Wave 2 a clear message.
- **1F undo granularity.** `EditPlan::into_transaction` hardcodes
  `TransactionKind::Programmatic` → discrete undo steps per SmartEnter/format. Confirm
  that's the intended UX in Wave 1; if runs should coalesce, thread the kind through.
- **1E export page cap.** `MAX_EXPORT_PAGE_BYTES` currently inherits the 96 MiB preview
  ceiling; pick a tighter "send to others" default once data-URI image inlining (§7-OQ1)
  lands.
- **LD-3 scope note.** `EditTransaction` stays public, so the no-rewrite guarantee is
  format-path-scoped. Wave 2 lints shell format handlers against building transactions
  directly instead of routing through `apply_format`/`EditPlan`.

### Wave 1 — Core engines (parallel lanes, core-only, no shell work)
- 1F Format engine: bold/italic/code/link/heading-cycle/quote/list toggles, smart
  Enter (list/quote/checklist continuation, double-Enter exit, ordered renumber).
  Property tests: idempotent toggles, selection preservation, no whole-buffer rewrites
  (edit-complexity rule holds).
- 1P `html_to_markdown`: bounded, allowlist-driven (same sanitizer philosophy as
  render), golden-corpus tests from real clipboard HTML (Safari/Chrome/Word/GDocs),
  new fuzz target `html_to_markdown` wired into the fuzz workspace.
- 1E Export: template with inlined token CSS (build step generates from
  `design/tokens.css`; tastecheck pipeline runs on the template — see Wave 3), body
  from the existing typed renderer, doctype/meta/print styles; byte-size gate;
  `validate no scripts/external refs` test mirroring the preview inspector.
- 1Q Core QoL: find/replace ops (plain + whole-word, no regex in 0.2), word/char/
  reading-time counters. Autosave journal format + recovery load in FileService.

### Wave 2 — Shell integration (2M macOS, 2L Linux, parallel; product tests each)
- Key bindings + edit-menu items + optional toolbar (hideable, native) for all
  FormatCommands; clipboard HTML capture for smart paste; Save-as/Copy-as-HTML
  gestures; find/replace bar; status-bar counts; native spellcheck enablement;
  autosave timer + crash-recovery prompt + session restore (last file, cursor,
  window frame).
- Product gates extended: each shell's product test suite grows scenarios for
  format-via-shortcut, smart paste, export file correctness (hash + inspector),
  recovery-after-kill, find/replace.

### Wave 3 — Design pipeline on the export template (LD-8a, strict)
- Run the tastecheck chain against the export template with real documents:
  color-system ramp generation from token anchors → web-typography scale →
  spacing-system → theming (light/dark/print/high-contrast) → responsive-layout
  (mobile widths) → component-states (edge-break hovers, focus) → micro-motion
  (reduced-motion) → a11y-pass + cognitive-a11y + i18n-ready (EN/ES samples) →
  deslop-ui audit against DESIGN-SYSTEM.md → **tastecheck-pass gate (mandatory)**.
  Visual verification in a real browser on macOS + WebKitGTK, light and dark.

### Wave 4 — Reviews and integration
- Independent read-only reviews per lane (code-reviewer for core engines, security
  eye on html_to_markdown + export inspector, qa-tester driving both real apps).
- Full workspace matrix on both hosts (Air + Niko incl. Wayland variant), fuzz smoke
  incl. the new html_to_markdown target (10k runs pinned + 15 min campaign).
- UltraQA round 2 targeting the new surfaces (hostile clipboard HTML, format-command
  storms at cap boundaries, export of hostile-but-renderable docs).

### Wave 5 — Release 0.2.0
- Version bump, both-platform artifacts via the locked packaging driver, evidence
  bundle `docs/evidence/local-beta-0.2.0/`, handoff doc update, PR, merge.

## Hard rules carried over
- No weakening of security/boundedness/copy-complexity rules to make a feature fit.
- Preview stays a no-input surface; export stays scriptless; no new network seams.
- 20 MiB document cap unchanged; format commands must respect incremental-edit rules.
- Any contradiction between this plan and repo state stops the lane and reports.

- Toolbar's final visual: native, minimal, follows the upcoming chrome design
